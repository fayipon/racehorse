# Sunny Cup 陽光盃

React + TypeScript 的純前端賽馬遊戲，Godot 4.7.2 Web 負責 3D 賽場、八匹小馬、跑步動畫與自動分鏡。沒有後端或真實金錢交易。

## 啟動

```sh
npm install
npm run dev
```

開啟 http://localhost:5175。固定使用 5175，埠被占用時會報錯。
本機已完成 Godot 匯出。全新 clone 或修改 Godot 後，請先執行下方匯出步驟。

## 遊戲規則

- 每輪固定 120 秒：投注 48 秒 → 集合倒數 12 秒 → 比賽 50 秒 → 結算 10 秒 → 下一輪。
- 集合、比賽與結算期間不能投注或撤單，所有判斷使用實際時間。
- 冠軍八選一：賠率 7.60。
- 冠軍單雙：單 1/3/5/7，雙 2/4/6/8，賠率 1.90。
- 冠軍大小：小 1–4，大 5–8，賠率 1.90。
- 賠率含本金。投注 100、賠率 7.60，中獎派彩 760。
- 初始 10,000 虛擬籌碼；每筆 10–10,000，須為 10 的倍數；每輪最多 100 筆。
- 沒有腳本的場次，八匹馬冠軍機率相同，預先生成的隨機排名不受投注影響；有腳本的場次，名次由 `races.json` 指定。動畫衝線順序與派彩一致。
- 籌碼少於 10 且本輪沒有注單時，可以免費補充 10,000 練習籌碼。

所有玩家共用 `races.json` 的時程與種子，同一時間看到同一場比賽；切到背景再回來，會直接接上大家的進度。本機只儲存餘額、本輪注單與自己的最近 12 場結果。重新整理、背景分頁或休眠後會按實際時間補結算，不會重複派彩。支援 Web Locks 的瀏覽器會序列化多分頁的籌碼操作。資料只存在此瀏覽器，純前端架構不具備防竄改或跨裝置同步功能。

## 語系

支援繁體中文、简体中文、English、日本語與 Português (Brasil)。大廳右上角切換，選擇存在瀏覽器（`racehorse-locale`），各盃頁面跟著換；第一次造訪依瀏覽器語言決定，其他語言一律用英文。

- 網址帶語言：大廳是 `/<語言>/`，各盃是 `/<語言>/<盃>/`，例如 `/racehorse/en/sunny/`、`/racehorse/zh-TW/`（`src/route.ts`）。分享的連結會用同一個語言開啟，打開帶語言的網址也會記成下次的預設。
- 切換語言時網址跟著換；沒有語言的舊網址（`/racehorse/sunny/`）依上次或瀏覽器的語言補上。
- GitHub Pages 是靜態主機，建置時 `vite.config.ts` 把每一頁在每種語言的資料夾再寫一份（只改 `<html lang>`），開發伺服器則把 `/<語言>/…` 對應到同一頁。`404.html` 把大小寫不同或多餘的路徑（如 `/EN/sunny/x`）導回正確的頁面。

- 介面文字在 `src/locales/<語言>.ts`，以繁中 `zh-TW.ts` 為型別來源，其他語言缺字或多字會在型別檢查時報錯。頁面只載入目前語言那一份（壓縮後約 4 KB）。
- 字型依語言載入：繁中 Noto Sans TC、簡中 Noto Sans SC、日文 Noto Sans JP，英文與葡文只用 Outfit。
- 馬名：英文與葡文用英文名，日文用片假名，簡中用簡體字；比賽中的即時排名一律顯示英文名。
- 轉播語音依語言載入（見下方「賽事轉播」）；簡中共用繁中的普通話錄音。

## Godot 與分鏡

用 Godot 4.7.2 開啟 `godot/project.godot`。原生編輯器執行的是循環鏡頭預覽；投注 UI 與帳本由 React 負責。

Web 匯出範本必須與 Godot 版本相同，使用 Compatibility renderer、單執行緒 Web 匯出，不需要 COOP/COEP。

```sh
npm run godot:export
```

此命令需 `godot` 在 PATH 中；也可直接在 Godot 編輯器中選擇 Web 預設匯出到 `public/game/index.html`。`public/game` 的 Web 匯出檔一併納入 Git，讓 GitHub Pages 建置不依賴 Godot 安裝。修改 Godot 後請重新匯出並提交。

## 賽事 JSON

前端是播放器，照著 `public/races.json` 播放：三個賽事的時程（`epoch`、`seed`），以及指定場次的名次、跑法、中途領先、終點差距與主播台詞。格式與編輯守則見 [docs/race-json.md](docs/race-json.md)。建置時設定 `VITE_RACES_URL` 可改從 API 讀取同樣格式；`src/raceScript.test.ts` 會在 CI 檢查出貨的檔案。

## 比賽跑法

每場的過程由 `src/raceModel.ts` 依場次種子產生，官方名次（`raceOrder`）與冠軍 44.5 秒到線都不變。八匹馬各有跑法：領放、跟前、中段後追、後段爆發。每匹馬「落後虛擬領頭馬幾米」是一條以冠軍進度為參數的單調三次曲線（Fritsch–Carlson），因此馬不會倒退，速度連續；起跑是約 1.1 秒的加速，之後穩定奔馳。

- 馬群緊湊：中段頭尾約 5–6 個馬身，位置逐步推移，一場平均換領先約兩次；約一半比賽有一匹馬在對面直路上前挑戰領先。
- 最後 400 米依跑法發力：領放馬撐住或被追上，後追馬從外側或內欄衝上來。終點差距約兩成是鼻位到頭位，其餘多在半個到兩個馬身，少數輕鬆勝出。
- 終點差距以進度計算，外圈馬即使每圈較長，也一定照官方名次越線；各馬完賽時間由曲線解出，傳給 Godot 與頒獎台。
- 畫面上的 1200 米是一圈約 277 米的橢圓，1 個馬身（2.4 米）約等於名目 10 米；轉播所說的馬身差距都以畫面距離計算。

React 把整場的比賽計畫（約 1 KB）隨賽事狀態傳給 Godot，`race_motion.gd` 以相同公式計算位置，兩邊的排名、小地圖與 3D 畫面一致。本機預覽與 Godot 測試使用 TypeScript 產生的 `godot/assets/race_preview.json`，`src/raceModel.test.ts` 確保它與產生器同步。

React 每 250ms 同步賽事時間，Godot 使用連續時鐘逐幀計算同一條進度曲線，避免追趕位置快照造成頓挫：

| 階段 | 分鏡 |
| --- | --- |
| 投注 | 賽前巡禮 |
| 比賽 0–7 秒 | 正面起跑 |
| 比賽 7–24 秒 | 側面追拍 |
| 比賽 24–34.3 秒 | 彎道追逐（對準領先群）；28 秒起畫面稍微加快（最多 1.13 倍），先存下慢動作要花的時間 |
| 比賽 34.3–38.3 秒 | 終點旁貼地長焦：馬群側身繞過最後一彎，再迎面衝出彎道（蓄力） |
| 比賽 38.3–42.6 秒 | 必殺技特寫：衝擊畫格、變焦重擊、斜傾低角度臉部特寫、約 2.65 秒的 0.35 倍慢動作 |
| 比賽 42.6–44.6 秒 | 爆發：最高約 1.5 倍速追回時間，貼地廣角跟拍 |
| 比賽 44.6–45.8 秒 | 衝線：衝擊畫格與震動，停格 1.2 秒並低角度大幅環繞冠軍，「率先衝線」冠軍橫幅滑入 |
| 比賽 45.8–50 秒 | 主看台內的固定高角度，馬群持續加速跑過終點 |
| 結算 | 冠、亞、季軍頒獎台與彩紙 |

同一分鏡內，跟拍鏡頭隨目標移動、只緩動構圖位移，快速奔跑的馬不會拖出畫面；分鏡之間一律直接剪接。必殺技段落有動畫風格集中線；衝擊畫格是暗墨底配金色輪廓，讓畫面變暗而非閃白。減少動態效果偏好會關閉衝擊畫格、震動、集中線與變焦重擊。

參考使用者提供的介面圖片與影片；比賽用的馬是 Viverna「Horses (Stallions)」付費授權的寫實模型與原生動畫（只在本機、不提交，沒有時改用 Quaternius 的 CC0 馬），場景由 Godot 程式建構。素材來源與重建方式見 `ASSETS.md`。

## 驗證與建置

```sh
npm test
npm run lint
npm run build
```

測試涵蓋階段時間邊界、封盤、撤單、全部投注規則、扣款與只派彩一次、休眠補結算、動畫衝線順序、資料與金額驗證。
現成馬模型可另用 `godot --headless --path godot --script res://tests/horse_smoke.gd` 驗證朝向、比例、骨架動作與待機切換。
部署前先匯出 Godot，再執行 build，將整個 `dist/` 作為靜態網站提供服務。瀏覽器需支援 WebGL 2。

## 檔案

- `src/game.ts`：純函式賽事狀態、共用時程、隨機排名、派彩、移動距離。
- `src/schedule.ts`、`src/raceScript.ts`、`public/races.json`：讀取賽事 JSON、驗證腳本、截止投注後鎖定場次。
- `src/useGame.ts`：共用時鐘、本機儲存、跨分頁操作鎖。
- `src/App.tsx`、`src/index.css`：投注、資訊、歷史與手機版介面。
- `godot/scripts/race.gd`：3D 小馬、賽場、動畫與分鏡。
- `godot/scripts/asset_horse.gd`：載入馬模型（Viverna 或 CC0 備援）、毛色貼圖與染色、LOD 與影子替身、依馬身自動貼合的號碼布與冠軍花環，以及 Idle / Walk / Gallop 動畫切換。
- `scripts/prepare_viverna_horse.py`：以 Blender 從 `vendor/viverna/` 的授權素材產生比賽用的模型與貼圖。
- `godot/scripts/race_track.gd`、`infield.gd`、`venue.gd`、`podium.gd`：跑道與欄杆、內場花園、主看台與大螢幕、冠軍圈；共用 `mesh_kit.gd` 程序化建模。
- `godot/web_shell.html`：Web 引擎載入與同源訊息橋接。

## 視覺與賽道更新

- 賽道為兩段長直線與兩端半圓。`godot/assets/course.json` 同時供 Godot 路線與 React 小地圖使用；起終點固定在近側直道中央。
- 跑道採修剪條紋草皮，內側另有一圈沙地訓練道。內欄是鵝頸柱撐起的白色圓管欄杆，外欄是雙橫桿白欄，對面直道外側有修剪樹籬；全部由 `race_track.gd` 沿同一條路線程序生成，欄杆合併成單一網格、立柱以 MultiMesh 繪製。
- 主直道後方是長 104 公尺的主看台：玻璃大廳、十排座位與觀眾、包廂層、九張帆布頂棚與桅杆旗幟、SUNNY CUP 招牌和金色太陽，看台前緣掛八色彩旗，前方石板步道有陽傘。
- 對面直道後方的大螢幕顯示場次與八匹馬的名次色塊：投注時依馬號排列，比賽中即時滑動到當下名次，結算時顯示正式完賽順序。螢幕後方是白綠條紋帳篷區與旗桿。
- 內場為斜格修剪草坪、中央噴泉池（水面反光、粒子噴水），最後彎道端是樹籬造型馬花園：石座上的綠籬馬、矮樹籬圈與花；兩側保留小樹群。
- 比賽中的即時排名列出全部八匹馬，各種寬度都是依名次滑動的直式八列。寬度 700 px 以下的直版畫面以遊戲畫面為主體：投注、比賽、結算三個階段賽場高度一致，3D 畫面都填滿整個賽場，操作介面疊在畫面下方。投注面板半透明浮在畫面上；比賽時排名、賽事進度與小地圖疊在底部漸層上，衝刺特寫時與寬版一樣暫時收起；結算的第 4–8 名清單同樣半透明，冠軍圈草坪延伸到畫面底部。直版的投注與比賽鏡頭改以畫面寬度取景（比原鏡頭角度寬 15%），多出的高度顯示草地與天空；冠軍圈鏡頭本身就會後退到三匹馬剛好入鏡。鏡頭再以平移投影把主體往上移，避開下方的介面：投注時移到畫面上方約四分之一，比賽時略高於中央，冠軍圈維持原本的位置。
- 載入：首次下載約 15 MB（gzip 後：引擎 10.1 MB、資源包 5.3 MB，其中寫實馬的模型、動畫與 1024 貼圖約 2.6 MB）。植物貼圖改為有損 WebP，資源包由 6.0 MB 減為 3.1 MB。WebGL 在材質第一次繪製時才編譯著色器，而且在頁面主執行緒上進行，這是下載完成後等待的主因。草地、草皮、沙道共用 `ground.gdshader`，樹葉、樹籬、旗幟共用 `foliage.gdshader`，馬匹與冠軍圈樹木也改用場景既有的材質組合，材質著色器由 22 組減為 12 組（含號碼布自己的一組），首幀編譯時間約少三成。場景分成五步逐幀顯示，每步只編譯幾組著色器，頁面持續更新；進度條前 70% 為下載，後 30% 為啟動，場景全部畫過一次後才淡入。
- 效能：桌面限 60 fps；賽場捲出畫面時 Godot 降到每秒 4 幀。網頁版不使用 `Engine.max_fps`：它在等下一幀時會讓頁面唯一的主執行緒空轉，60 Hz 手機跑 30 fps 時主執行緒九成時間被佔滿；改由 `web_shell.html` 跳過提早到來的 `requestAnimationFrame`，引擎只在該畫下一幀時才被喚醒（`race.gd` 的 `set_frame_rate`）。頁面約每秒傳四次狀態，Godot 只在版本號變動時才解析。每匹馬各部位的顏色寫進頂點、號碼布與滾邊合成一片，號碼由布料著色器直接印上，每匹馬由 10 個繪製呼叫減為 2 個；植栽依象限分批，繪製呼叫由 672 降到 312。觸控裝置自動進入省電模式：30 fps、渲染解析度上限 1.5 倍（手機原生約 3 倍）、觀眾約四成、較少遠景樹與草叢、關閉 MSAA 與光暈、較小的陰影貼圖、陰影由四層改為兩層，並停用賽場上的毛玻璃模糊。觀眾是畫面上最大宗的三角形，省電模式把每個觀眾模型的頂點吸附到粗網格上合併（`venue.gd` 的 `weld`），三角形約少八成；在手機上每位觀眾只有幾個像素高，輪廓與服裝顏色不變。投注與比賽時每幀繪製的三角形（含陰影）由約 110 萬降到約 43 萬。
- 投注期間每匹馬每輪有獨立的散步行程：不再固定來回折返，會停下、繼續往前或轉身，步速各不相同；停下時隨機吃草、張望、低頭休息或站立。Godot 讓馬在跑道內橫向漫步、走成弧線，出發前先原地踏步轉向，不會倒退走；相鄰的馬並排時由走動的一方繞開，站著的馬不會被推著滑動。散步區在起跑閘門後方：第 47 秒起各自走到自己閘位的線上（距離遠的轉身走過去，近的原地側步），第 49.7–56 秒直直走進閘位，鼻尖貼著前門，第 60 秒開閘。小地圖使用同一份行程。`godot/tests/parade_smoke.gd` 驗證不倒退、不重疊、不滑步、不碰到閘門與準時進閘。
- 起跑閘門（`starting_gate.gd`）不分賽事固定 12 門，置中橫跨跑道，閘位號碼牌與前門色帶用各號馬的顏色；8 匹與 10 匹的賽事用 1–8、1–10 號閘位，出閘後約 70 米內散開到自己的跑道。前門在開賽瞬間彈開，閘門在第一次換鏡頭時撤走，衝線時終點線保持淨空。閘位深度與高度依目前的馬模型設定，換模型時調整檔頭的常數即可。`godot/tests/gate_smoke.gd` 驗證進閘、開閘、散開與撤走。
- 馬匹使用 Viverna 的寫實種馬模型與原生奔跑／走路／待機／吃草動畫，12 種天然毛色由 5 張毛色貼圖染出（見 `ASSETS.md`）。桌機畫約 7,000 面的 LOD1、手機畫約 2,400 面的 LOD2，影子一律由 780 面的 LOD3 投出，畫出的馬身不投影。號碼布依馬身橫切面自動貼合、沿用馬身骨架權重，換模型時不必重畫；布面有絎縫、滾邊與印上的號碼。走路依實際移動距離推進，蹄不會在地上滑；奔跑維持賽馬每秒約 2 步的節奏。沒有授權素材時改用 Quaternius 的 CC0 低多邊形馬；原程序小馬模型保留於 `pony.gd` 供比較。
- 光照為午後暖陽：Filmic 色調映射、輕微光暈與飽和度調整；太陽從主直道鏡頭左側斜照，讓馬匹有立體明暗，看台陰影主要落在步道上。鏡頭方向的柔和補光只照亮小馬，改善起跑背光。
- 樹木、灌木、草叢、花卉與石頭採用 Quaternius Stylized Nature MegaKit 的 14 個免費 CC0 模型。內圈草邊、端部小樹群與外圍林帶有不同密度和尺度；短草坪、天空漸層與遠景薄霧增加自然層次。植栽依空間分成 MultiMesh 批次，共用貼圖，風動尊重減少動態效果偏好。
- 現成模型的骨架驅動腿、頭部與尾巴，動作之間淡入淡出；各馬有不同步點、步頻及緩慢節奏變化。最後衝刺逐漸提高步頻，馬蹄草屑留在經過的位置後淡出，並隨衝刺增強。
- 終點是橫越草地的白色終點線，內側立著紅圈終點柱；內欄旁每 200 公尺有紅白距離桿，標示剩餘距離 1000–200。外側不放任何建物，終點鏡頭的移動路徑保持淨空。
- 衝線後的彩帶從整個賽場畫面上方分散飄落，各有不同大小、落速、擺動與翻轉；切換終點定鏡與頒獎時持續落下，下一輪投注清除。減少動態效果偏好會降低數量及落速。
- 攝影機跟著馬群中心移動，從對面彎道起逐漸轉向當下的前段馬群，不跟隨身體彈跳。只有移動中的跟拍鏡頭會在畫面邊緣加上水平動態模糊，長焦、慢動作、停格與看台固定鏡頭都保持清晰；減少動態效果偏好會停用模糊並減少揚塵。唯一的震動只在衝線衝擊的 0.4 秒內。
- 衝刺段加上電影黑邊，演出像必殺技：38.3 秒切入領先馬的慢動作特寫，釋放後加速貼地衝向終點。冠軍越線瞬間出現衝擊畫格與震動，停格 1.2 秒，馬匹與揚塵暫停、鏡頭低角度大幅環繞；React 同時滑入斜切的「率先衝線」冠軍橫幅並暫時隱藏底部 HUD，46.4 秒後換成冠軍宣告。停格解除後先升至 1.35 倍，再持續加速至結算時的 1.9 倍，鏡頭切到主看台內的固定構圖，背景保持清晰；馬匹不再降回正常速度。位置、步態、小地圖與進度採同一條播放時間曲線（`godot/assets/cinematic.json`），冠軍仍在 44.6 秒到線，八匹馬仍在 50 秒結算前完賽。
- 結算切到獨立的冠軍圈：弧形綠色背板與金色立柱、白色大理石頒獎台與金銀銅獎章、與賽場同款樹木的盆栽，冠軍脖子掛黃橙色花環並有暖色聚光。只有前三名馬匹正面特寫：冠軍居中、亞軍在左、季軍在右。第四至八名依實際完賽順序，以五列清單顯示在前三名看台下方，包含名次、馬號及中英文馬名；結算畫面為清單預留空間，投注紀錄另置底部。馬匹與賽果每輪更新，彩紙延續到結算結束。
- 馬匹越線後維持奔跑步態與入線速度，依同一條播放時間曲線持續加速前進，揚塵沿實際路線延續，鏡頭留在終點線直到切換頒獎台；完賽名次及派彩仍以首次越線為準。
- `dev/visual-preview.html` 是獨立的開發視覺預覽，可切換分鏡與俯視跑道，不讀寫玩家投注資料，不會納入正式 build。
- `dev/ceremony-preview.html` 使用正式賽場 UI 預覽特寫、衝線與前三名展示，可暫停與播放，也不讀寫玩家投注資料。
- `scripts/sculpt_pony.py` 可重新生成雕塑網格（需要 Python 與 numpy）。Godot 直接使用已保存的 OBJ，執行遊戲不需要 Python。

## GitHub Pages

網站：https://fayipon.github.io/racehorse/

推送 main 後，GitHub Actions 自動執行測試、lint、建置與 Pages 部署。
本機預覽使用 `npm run dev`；Pages 使用 `npm run build -- --base=/racehorse/`。

GitHub Pages 在部分網路很慢（台灣實測約 50 KB/s，同一條線連 jsDelivr 約 10 MB/s），所以部署版的大檔改從 jsDelivr 的 repo 鏡像下載：Godot 引擎、資源包、轉播語音與觀眾聲。每個檔案釘在最後修改它的 commit（`scripts/mirror.ts`），網址只在檔案變動時才改變，瀏覽器可快取一年；鏡像失敗或 10 秒內沒有回應就改從 Pages 下載。jsDelivr 不收超過 20 MB 的檔案，引擎因此以 gzip 副本 `mirror/index.wasm.gz` 提供，由頁面以 `DecompressionStream` 解壓；`npm run dev`／`npm run build` 前的檢查會在匯出更新後重建這份副本，請與匯出一併提交，CI 發現不一致會停止部署。部署前 CI 會先抓一次每個鏡像檔，讓第一位訪客不必等 jsDelivr 回 GitHub 取檔。載入畫面只在進度停滯 60 秒時才顯示失敗，慢速網路下仍會持續下載。

## 賽事轉播

從投注期間的賽前閒談，到開跑後一路播到宣布冠軍的現場轉播，語氣參考 `design/` 內的 Fish Audio 試驗音（最後 200 米外側追上、一個馬身、半個馬身、並排、最後一步逆轉）。

- 開閘時整場賽果已知，`src/commentary.ts` 事先排好整場口播：先固定開閘、衝線（馬名喊兩次、衝線瞬間正好在「衝過去了」之中）、結果判定與二三名，再依參考音的順序排最後 200 米：領先馬撐住、點出追兵（依跑道內外說「外面的」或「內欄的」）、越追越近、一個馬身、半個馬身、並排、衝出來了、還在頂。每句都以唸到當下的畫面判斷。
- 投注期間是慢慢說的賽前閒談（語速較慢、句間停頓約 1.2 秒）：開場問候、依真實賽果的近況（上一場冠軍能否連勝、最近都在前三、連贏兩場、上一場只拿第二、最近不太順）、每匹馬固定的兩則瞎掰背景故事（例如赤焰去年受傷、上個月才復賽）、依本場跑法的預告（誰喜歡一開始就衝、誰末段腳力驚人），以及指出畫面上正在吃草、張望或低頭休息的馬；接著提醒下注、宣布封盤集合，倒數前說「全場安靜下來，準備開閘」。
- 前段報領先易主、第一彎道、剩餘距離、對面直路、最後彎道與 400 米發力的馬；空檔補報名次、內欄或外側、中段、壓後等待與慢慢推進的馬。報到名次的句子逐段組成，每個馬名都是唸出那一刻在那個位置的馬。
- 結果判定：最後 60 米內換領先為「最後一步逆轉」，最後 400 米內為「漂亮的逆轉」，剩 800 米前就領先為「一路領先到終點」，差距兩個馬身以上為「輕鬆勝出」；差距不到四分之一馬身時喊「鼻位之爭！要看終點照片！」。
- 語句庫在 `scripts/commentary/<語言>.json`（`zh-TW`、`en`、`ja`、`pt-BR`），四種語言使用相同的片段 ID，同一套排程適用每種聲音。通用句、依馬名展開的句型與背景故事，另有依盃別錄製的開場（歡迎來到陽光盃／雷霆盃／皇家盃）與依場上馬數錄製的開閘句；分閒談、平穩、升溫、高潮四級語氣。`python scripts/generate_commentary.py --lang <語言>` 生成、切齊靜音、依級別統一音量後合成 `public/audio/commentary/<語言>/voice.mp3`（陽光盃八匹馬）與 `voice-extra.mp3`（第 9–12 號馬與十、十二匹的開閘句，只有雷霆盃、皇家盃載入），32 kbps，開啟聲音時才下載目前語言那一份；片段位置寫入 `src/commentary/<語言>.json`。
- 播放器以音訊時鐘提前 1.2 秒排程，句子對準畫面上的時刻，包含慢動作與衝線停格；聲音在比賽中途開啟時從下一個完整句子開始。播報時觀眾聲自動壓低，說完再回升。
- 聲音皆為 Fish Audio 公開聲音，以 S2.1 Pro 免費模型 `s2.1-pro-free` 生成：普通話「影視解說」、英文「Sports commentary」（英式口音）、日文「アツ実況」、葡文「KAI」（巴西口音）；外語聲音從試聽中挑衝線時情緒拉得最高者，排除模仿真人的聲音模型。每句開頭加方括號語氣提示，閒談是溫和的廣播語氣，衝刺是吶喊的賽馬主播。聲音 ID 與引擎寫在各語言的語句庫；需要 `FISH_API_KEY`（環境變數或不納入版本控制的 `.env.local`），`FISH_CONCURRENCY` 可調同時請求數（預設 2）。`--preview` 只生成一段試聽，`--voice` 可試其他聲音；`--engine edge` 可改回免費的 Edge 語音。
- `src/commentary.test.ts` 驗證每句都有錄音、不重疊、冠軍與二三名正確、衝線落在句中，並檢查報領先、名次與馬身差距的句子符合當下畫面；每種語言都要錄齊同一組片段，三種盃別的整場口播都要在比賽時間內說完。

## 觀眾歡呼

音效開關同時啟用賽事轉播與三層觀眾聲浪：現場底聲、歡呼與高潮吶喊。各層持續循環，最後彎道前開始平滑堆高，衝線到結算維持高潮，結算結束後以 5 秒漸弱收尾，避免階段切換造成中斷或突然拉高音量。素材出處與授權見 `public/audio/crowd/LICENSE.txt`。

初始靜音，點擊開關啟用；切到背景或關閉音效停止。

`scripts/prepare_crowd_audio.py` 可重新處理歡呼素材。
